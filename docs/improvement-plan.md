# SlideX 后续改进规划

基线：1.7.0-rc.7。第一至第四批已完成本批实现并纳入 rc.7 本地构建；各批日期与“尚未打包进 rc.6”说明保留为历史记录。当前剩余能力与下一阶段优先级见 [rc.7 后续能力规划](next-capabilities.md)。未勾选项均为计划，不代表已实现。

## 目标与约束

- 保留 React 编辑器、ProseMirror 和共享渲染器，继续完善现有架构。
- 优先解决导出信息丢失和文档稳定性，再增加编辑便利性和内容种类。
- 新增 DSL 能力先完成规范、解析、校验、序列化及共享渲染，再接入编辑器；已有能力的交互优化不等待语言扩展。
- 保持既有文档兼容，保留对象 ID、内部链接和动画目标；不得静默丢弃未知或不支持的内容。
- 不承诺跨渲染引擎像素完全一致。区分原生可编辑、栅格化保真和不支持的能力，并明确告知用户。
- 本规划不包含完整 PPTX 导入、无损往返、多人实时协作、跨组拖拽或复杂重组。

## 当前基线

已具备：原位富文本、嵌套组内编辑、图片裁剪、表格单元格与合并拆分、图表数据编辑、母版和主题、对象锁定、撤销重做、动画顺序与触发、演讲者视图、桌面偏好设置、原生导出位置选择、DSL 格式化和检查、指定页面范围图片导出。

主要缺口：

| 领域 | 当前边界 | 改进目标 |
| --- | --- | --- |
| PPTX | 原生表格、组合、五类基础图表及动画子集已有，超出子集明确回退 | 扩展原生图表/动画覆盖；字体嵌入与兼容性验收 |
| 页面管理 | 多页选择及批量复制、删除、移动已有 | 页面分节、命名检索、模板与布局复用 |
| 图层与定位 | 层级树、显隐、重命名、标尺与固定参考线已有 | 连接线锚点、路径控制点与更完整的样式复用 |
| 形状 | 源码已具备 36 种预设、参数控制点及自定义路径 | 后续按使用反馈扩展曲线预设的原生导出 |
| 图表 | 源码新增雷达、气泡、瀑布；基础五类支持原生导出子集 | 扩展原生样式，双轴与其他图表另立任务 |
| 动画 | 源码新增旋转、颜色、退出、路径及时间线 | 逐步扩展原生导出和高级时间线 |
| DSL 工程化 | 多文件、补全/定义定位、格式化、检查、图片清单、CLI 与 Skill 已有 | 按 ID 增量修改协议、跨文件重命名、独立语言服务 |
| Viewer | 当前页及相邻页按需挂载，媒体缓存与性能基线已有 | 独立触屏交互、多屏恢复与富媒体压力验收 |

基线入口：`src/ir.ts`、`src/export/pptx-native.ts`、`web/Player.tsx`。功能数量是当前代码的能力边界，不是产品完成度百分比。

## 第一批：导出可靠性（P0，已完成本批实现）

2026-09-20：A1～A3 的本批实现已落地，详情见 [导出可靠性实现与验收](export-reliability.md)。本批不包含字体嵌入、原生图表或原生动画；明确回退边界后交付。当前为源码更新，尚未生成新的桌面发布包。

### A1：能力报告与回归基线

- [x] 建立按对象和属性划分的导出能力矩阵：原生、栅格化、不支持。
- [x] 输出包含页面、对象 ID、回退原因和建议的报告；界面显示摘要，CLI 提供机器可读结果。
- [x] 区分成功、带降级成功、取消、失败；取消选择路径不得留下半成品，失败不得破坏已有目标文件。
- [x] 建立中文字体、富文本、旋转翻转、嵌套组合、裁剪、合并表格、图表、公式和动画样例集。

验收：每个回退对象可定位；PNG/PDF/PPTX 的页数与页面范围一致；保留导出前提交编辑状态及保存位置选择的回归检查。PPTX 包结构自动检查之外，必须用实际 PowerPoint 打开，确认无修复提示；无法进行真实应用验收时明确记录未验证项。

### A2：原生表格导出

- [x] 导出行列尺寸、合并单元格、填充、边框、对齐及受支持的富文本。
- [x] 明确复杂单元格内容的回退粒度，禁止静默丢失文字或合并关系。

验收：PowerPoint 中能修改单元格文字和表格结构；长中文、多行、合并、非等宽列的样例无缺失，保存后仍能重新打开。

### A3：原生组合与字体策略

- [x] 递归导出受支持的组合子元素，正确转换嵌套、旋转、翻转和缩放坐标。
- [x] 保留可映射的对象关系；不支持的子对象采用最小必要范围回退。
- [x] 检测缺失字体并显示替代信息；评估字体嵌入的格式、授权与应用兼容性，明确支持范围后再实施。

验收边界：镜像文字/表格按对象回退以保留视觉；含公式表格整表回退；PowerPoint 可能归并嵌套层级，但源文档结构与 ID 不变。字体检测不保证全部字形覆盖及目标设备字体一致，字体文件嵌入留待后续。

验收：组合在 PowerPoint 中可选择并编辑子元素；导出不改变源文档 ID；在字体可用和缺失两种环境下分别记录布局表现。字体嵌入的调研不阻塞 A1/A2。

## 执行与完成标准

实施顺序：A1 → A2 → A3 → 第二批 → C1 → C2 → C3 → 第四批。每批拆成可独立验收的提交；先审计现有实现，避免重复实现已完成的功能。

功能批次须完成对应核心测试、编辑器交互回归及必要的桌面实机验收；使用项目现有 `npm test`、`npm run test:react`、`npm run test:electron`，按改动范围选择适用检查。涉及导出的批次额外记录真实 PowerPoint/PDF 打开和视觉检查结果。纯文档更新无需运行构建和功能测试。

只有代码、测试、使用说明和已知限制均更新后，才能勾选完成。自动化无法验证的输入法、字体或目标应用行为，不以“单元测试通过”代替人工验收。
