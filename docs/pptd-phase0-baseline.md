2026-09-28。此文记录静态格式审查、真实 PPTD 项目清点，以及公开 Kimi 编辑器的有限浏览器探测。这里的“支持”只表示代码或规范中有对应能力；跨产品视觉一致性需要同页渲染对照，尚未验收。

## 输入与复现

- PPTD 样本根目录：`G:/github/mylessons/pl/ppt`。
- 格式定义：`tools/open-deck-skill/skills/open-kimi-ppt/reference/pptd.md` 与 `reference/shapes.md`。这是非官方逆向规范；实际线上行为以浏览器验证为准。
- Kimi 编辑器镜像：`tools/kimi-editor-mirror/neo-ppt.html`。该目录只有线上编辑器入口和通信脚本，没有编辑器主代码。旁边的 `open-deck-skill/editor/` 是第三方本地文件宿主。
- SlideX 基线：当前工作树的 `src/ir.ts`、`src/types.ts`、`src/project.ts`、`web/Inspector.tsx`、`web/SourceWorkspace.tsx`、`src/export/`。

在 SlideX 仓库根目录运行：

```powershell
python scripts/pptd-phase0-inventory.py G:\github\mylessons\pl\ppt --output docs/pptd-phase0-inventory.json
node scripts/pptd-phase0-editor-probe.mjs G:\github\mylessons\pl\ppt\tools\open-deck-skill --inspect-selection
```

第一条命令只读取样本，需 PyYAML。第二条启动临时本地宿主，连接公开 Kimi iframe，加载宿主自带的两页演示，不上传课程项目，也不写课程文件。探测脚本保存临时截图；本次截图留存为 [Kimi 编辑器示例](pptd-phase0-kimi-demo.png)。线上页面或协议更新后须重新探测。

## 阶段 1 前需要补的差分样例

真实课程页优先用于字体、主题、矩形和表格。另需按 PPTD 规范准备小型合成项目，至少覆盖以下组合，并在 Kimi 和 SlideX 中分别记录解析、UI、预览与 PPTX 结果：

1. 常用与边界形状、调整参数、自定义路径；先建立 177 种形状图集和名称映射。
2. 竖排文字、Latin/EA 不同字体、文字渐变与段落间距。
3. 图片的正负裁剪、cover/contain/fill、预设与 custom 蒙版。
4. 现有 8 类图表的双轴/样式，再覆盖其余 5 类的数据协议。
5. 入场、强调、退出与路径动画，含重复、延迟及切页重置。
6. 16:9、4:3、1:1、竖版，以及字体缺失/替换情形。

每例应保留 PPTD 源文件、等价 SLX、两种画布截图、两种 PPTX 和差异记录。当前没有 PPTD 导入器，等价 SLX 必须人工审阅其字段映射，避免把转换误差归咎于渲染器。

## 根据本次样本调整的优先级

针对这批课程，先做 **PPTD 导入映射设计及 Latin/EA 字体语义**，随后验证基础文本、矩形、表格和线条的同页视觉效果。扩充 177 种形状和复杂图表仍是通用格式差距，但这些课程项目没有用到，不能用本样本证明其紧迫程度。实现阶段应保留基础对象的编辑器交互、保存往返和导出降级报告检查。
