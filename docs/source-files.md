# 保留文件组织的多文件编辑

入口可以是 `main.slx`，通过 `<include>` 引用独立页面或章节。打开入口后，画布仍呈现整套幻灯片；保存按源码归属写回原有 `.slx` 文件，保留文件名和 include 结构，不再创建 `.slidex-pages/` 快照。

## 画布写回规则

- 页面内容、位置、样式和备注写回拥有该页面的原文件。一个章节包含多页时，只修改对应页面范围。
- 全局主题、字体、母版和文档设置留在入口文件。
- 未修改的文件完全不写入。普通属性或文本编辑尽量保留原有引号、空白和其他区域的注释；增删对象等结构变化可能重新序列化所在区域，并丢失该区域内的注释。源码工作区可直接控制实际文本。
- 新页面跟随最近的已有页面，写入它所在的文件。独立 `<slide>` 文件需要容纳零页或多页时转换为 `<slides>`。
- 页面重排按新顺序填入保留的原页面位置，因此跨章节拖动可能迁移多个页面的内容。include 顺序和文件名保留，但页面与文件的对应关系可能变化。若要精确控制章节归属，请在源码中调整 include 或页面。
- 本地媒体路径按目标文件的目录重新计算，仍指向同一项目资源。建议始终显式设置稳定的页面和对象 ID。

旧版项目如已引用 `.slidex-pages/`，会写回当前引用的那些文件；不会自动恢复更早的人工文件组织，也不会删除旧快照。

## 源码工作区

工具菜单 → DSL 源码与检查，或直接打开 `/source`。

多文件项目左侧提供项目目录的可折叠文件树。点击目录按需加载下一层，点击 `.slx` 文件打开逐文件标签；尚未被入口引用的 SLX 也可打开、编辑和保存，并标记“未引用”。文件树不会进入 `.git`、`node_modules` 等工具目录，也不会跟随目录链接。刷新按钮重新读取目录列表，保留编辑缓冲；各文件具有独立的 Monaco 撤销记录。右侧显示当前文件大纲和整份项目诊断，点击诊断可跨文件定位。标签显示文件名，面包屑和悬浮提示展示相对路径。

在引用属性内按 F12，可跳转 include、`href="slide:…"`、母版、动画目标及主题颜色/样式定义。补全仍以当前文件的轻量语言接口为基础；尚无全项目重命名和完整 LSP。

“验证并应用”校验整份项目并更新画布，不立即写入磁盘；“保存”或 Ctrl+S 将所有已打开文件的修改一起写回原文件。未引用文件检查 XML 语法及 SLX 根节点，不参与当前文稿的主题、页面 ID 或媒体语义校验；加入 include 后才参与整份项目校验和画布显示。未应用的源码修改离开时会询问是否丢弃。注释修改也计入未保存状态。已应用源码缓冲随恢复草稿保存，只有磁盘项目版本和各源码文件哈希匹配时才恢复原始文本；未应用的输入仍需先应用或保存。画布撤销处理页面模型，注释等纯源码修改应在源码编辑器中撤销。

可在入口或章节中引用项目内已有文件，应用后刷新引用标记；当前界面没有新建、重命名或删除磁盘文件的操作。删除 include 不会删除被引用文件，该文件的编辑缓冲作为“未引用”保留，保存时仍写入其原文件。浏览范围限于入口文件所在目录及子目录。

## 冲突与恢复

保存校验整个依赖图的内容哈希，外部修改、缺文件或无效项目会阻止写入。多文件保存先生成 `.slidex-save-*.json` 恢复记录，再逐文件以同目录临时文件替换。普通写入失败会回滚已写文件；中断后重新加载入口会恢复未完成的保存。若文件又被外部修改，保留恢复记录并报错供人工处理。

这是可恢复的多文件提交，并非文件系统级原子操作；不承诺断电持久性，也不能锁住不遵守本地协议的外部进程。恢复记录包含修改前后源码，完成后会删除。单文件逐次替换同样使用这条保存路径。

## 本地 API

POST `/api/source-tree` 接收 `{expectedPath, expectedVersion, directory?}`，返回指定目录的下一层目录及 SLX 文件，不递归扫描全项目。POST `/api/source-file` 接收相同的版本参数及 `file`，返回 `{path, name, xml, hash, referenced}`。

POST `/api/source-project` 接收 `{expectedPath, expectedVersion, files?: [{path, xml, hash?}], xml?: string}`。`files` 是源码缓冲；可选 `xml` 是需要映射回源码的画布文档。响应包含组合 XML、原文件列表（含 `hash/referenced`）、页面归属、诊断和 `sourceChanged`，预览不写盘。未引用文件发生修改时必须携带打开时的 `hash`。

POST `/api/source-definition` 使用同样的版本和缓冲参数，并增加 `{file, offset}`；返回 `{definition: {file, line, col}}` 或无定义。偏移按 UTF-16，行列从 1 开始。

POST `/api/save` 在原有参数上增加 `sourceFiles`，将已应用源码和后续画布改动一起保存。文件必须存在且位于入口目录内；未引用文件也使用版本检查和同一恢复事务。冲突返回 409。CLI patch 也复用同一原文件写回逻辑。
